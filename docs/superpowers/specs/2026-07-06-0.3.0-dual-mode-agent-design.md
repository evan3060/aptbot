## 1. 总体架构与桌面 agent 模式

### 1.1 核心调整

0.3.0 主打**桌面 agent 模式**，WebUI 为核心交互入口。CLI 仅保留必要管理命令。

| 维度 | 设计 |
|---|---|
| 主交互入口 | WebUI（桌面 agent 模式） |
| 双轨共存方式 | 并列选择（每次开 session 选一个 agent，session 内不混用） |
| Mode A skill 选择 | 聊天框上方 skill chip 区，点击填模板 |
| 会话列表结构 | 树形：agent 为父节点，session 为子节点 |
| 专业 agent 创建 | 创建时自动开新 session |

### 1.2 核心洞察：统一抽象

Mode A 和 Mode B **不是两套独立系统**，而是**同一个 AgentProfile 抽象的两种配置实例**：

```
AgentProfile（统一实体）
│
├── Mode A 实例：default agent
│   ├── personality: 通用助手（固定 systemPrompt）
│   ├── skillScope: global（用户从 skill chip 区显式选）
│   ├── memory: none（session 级，不跨 session 积累）
│   └── 演化: 无
│
└── Mode B 实例：english-tutor / code-reviewer / ...
    ├── personality: 自定义
    ├── skillScope: bound（专业 agent 不显示 skill chip 区）
    ├── memory: shared（跨 session MEMORY.md，自动注入）
    └── 演化: 0.3.2 引入 SKILLS.md / STYLE.md
```

### 1.3 关键设计决策

1. **default agent 自动创建**：每个用户首次访问时自动创建私有 `default` agent（Mode A 入口），即开即用，零配置成本
2. **session 必须归属 agent**：新建 session 时必须指定 agentId（default 也是合法选择），session 内 agentId 不可变
3. **并列选择，不混用**：用户每次开 session 选一个 agent，session 内不切换 agent
4. **统一存储路径**：所有 agent 都在 `data/users/<userId>/agents/<slug>/` 下，default 与 english-tutor 平级
5. **skill 选择不持久化**：一次性使用，agent 自行判断后续是否继续用，用户可立即切换其他 skill

### 1.4 0.3.0 范围（双轨骨架）

| 模块 | 范围 |
|---|---|
| **基础架构（双轨共用）** | AgentProfile 实体 + session↔agent 强约束 + 自动迁移 + 跨用户隔离 + 路径防护 |
| **Mode A（通用 agent）** | default agent 自动创建 + skill chip 区 + skill 展示 UI 配置（不动 skill 文件 / 不动 AGENT.md）+ skill 模板填充（智能 / `{{cursor}}`）+ 不持久化 |
| **Mode B（长期 agent）** | 自定义 agent 创建（modal / 单页分段 / 自动开 session）+ MEMORY.md 自动注入（KV 缓存）+ read_agent_memory + write_agent_memory（自动写入 / 审计日志）+ 删除归档 |
| **左侧栏** | 树形结构（通用助手根节点 + 专业 agent 子节点 + session 叶节点）+ ⚙️ 设置按钮 + 新建专业 agent 按钮 |
| **CLI** | `/agent` `/agent info` `/agent memory-log` `/skill` `/skill use` |
| **API** | `/api/agents` 系列 + `/api/agents/default/ui-config` + `/api/skills` |

### 1.5 推迟到后续版本

- 0.3.1：Mode B 半自动积累（自动提议时机 + 分类积累独立文件）+ Mode A 体验优化（chip 排序 / 添加 UI）+ MEMORY.md 自动压缩触发
- 0.3.2：Mode B 演化（SKILLS.md 动态绑定 + STYLE.md 半自动写入）
- 0.3.3+：归档管理 UI / 恢复归档 agent / skill 拖拽 / skill 搜索

## 2. AgentProfile 数据模型与新建流程

### 2.1 数据模型

```
data/users/<userId>/agents/<slug>/
  AGENT.md            # personality + 配置（所有 agent 都有）
  MEMORY.md           # 跨 session 记忆（仅专业 agent）
  memory.log.jsonl    # 写入审计日志（仅专业 agent）
  sessions/
    <sessionId>.jsonl
    <sessionId>.meta.json
  ui-config.json      # UI 层配置（仅 default agent）
```

### 2.2 AGENT.md 格式

```markdown
---
name: 英语老师
description: 英语学习助手，专注语法、词汇、口语训练
userId: <userId>
type: default | professional
slug: english-tutor-a1b2c3
createdAt: 1719700000000
updatedAt: 1719700000000
---

你是英语学习助手，语调亲切，鼓励用户尝试表达。
重点：纠正语法错误时先肯定再修正，提供地道表达建议。
```

**frontmatter 字段**：
- `name`：显示名（中英文 / 任意字符 / max 64 / 可改）
- `description`：一句话描述（侧边栏显示 / max 120 字符）
- `userId`：归属用户
- `type`：`default` 或 `professional`（区分 Mode A / Mode B）
- `slug`：路径标识（自动生成 / `[a-z0-9-]{3,64}` / 不可改）
- `createdAt` / `updatedAt`：时间戳

**LLM 配置字段**（agent 级，影响新会话）：
- `model`：从 config.providers 的所有可用 model 下拉选
- `temperature`：0-2，默认 0.7
- `maxTokens`：默认 4096
- `reasoningEffort`：low / medium / high（仅支持的 model 显示）
- `thinkingType`：enabled / disabled（仅支持的 model 显示）
- `thinkingBudgetTokens`：仅 thinkingType=enabled 显示
- 未设置时 fallback 到 config.defaultModel + 系统 default 值

**body**：systemPrompt 正文（personality）

### 2.3 name vs slug 分离

| 字段 | 含义 | 可改 | 格式 |
|---|---|---|---|
| name | 显示名（侧边栏 + 设置浮层显示） | 可改 | 中英文 / 任意字符 / max 64 |
| slug | 路径标识（目录名 + agentId） | 不可改 | 自动生成 / `[a-z0-9-]{3,64}` |

**slug 自动生成规则**（实施阶段确定具体算法）：
- 从 name 生成：中文 name 用拼音/翻译转换 + 随机短后缀保证唯一
- 或：直接生成 UUID 短前缀（如 `agent-a1b2c3`）+ 与 name 完全解耦
- 用户不感知 slug，只看到 name

**name 修改时**：仅更新 AGENT.md frontmatter 的 name 字段，不动 slug，不动目录路径。

### 2.4 type 字段差异

| 维度 | type=default | type=professional |
|---|---|---|
| personality | 通用 systemPrompt（固定） | 自定义 |
| skill chip 区 | 显示（用户从 visibleSkills 配置选） | 不显示 |
| MEMORY.md | 无 | 有（启用记忆时） |
| memory.log.jsonl | 无 | 有（启用记忆时） |
| ui-config.json | 有（visibleSkills 配置） | 无 |
| 演化能力 | 无 | 0.3.2 引入 |
| 可删除 | 不可删除 | 可删除（归档） |
| 创建方式 | 自动创建 | 用户手动创建 |

### 2.5 MEMORY.md 内容结构（通用化）

```markdown
# Agent Memory

## User Profile
- 偏好正式语调
- 常用工具：VSCode + TypeScript

## Facts
- 用户当前角色：前端工程师
- 项目使用 React 18 + Vite

## Preferences
- 代码风格：函数式 + 不可变
- 回答语言：中文

## History
- 2026-07-06 讨论了 agent 双轨架构
- 2026-07-05 review 了 PR #42
```

**通用 section 分类**：
- **User Profile**：用户身份、角色、长期属性
- **Facts**：领域事实、项目背景、技术栈
- **Preferences**：用户偏好、习惯、风格
- **History**：重要对话历史、决策记录（追加为主，较少修改）

- Markdown 纯文本，无 frontmatter
- 软上限：≤ 8KB（超出后触发压缩机制）

### 2.6 SessionMetadata 扩展

[SessionMetadata](file:///Users/evan/projects/aptbot/src/core/memory/types.ts) 新增字段：

```typescript
export interface SessionMetadata {
  readonly id: string;
  readonly createdAt: number;
  readonly updatedAt: number;
  readonly label?: string;
  readonly passedSessions?: number;
  readonly userId?: string;
  readonly agentId: string;      // 新增：必填，归属的 agent
}
```

- 新建 session 必须指定 agentId
- agentId 在 session 创建时确定且不可变
- 现有 sessions 自动迁移到对应用户的 `default` agent
- 不持久化 activeSkill（skill 一次性使用）

### 2.7 系统访问约束

[systemPrompt 约束](file:///Users/evan/projects/aptbot/src/server.ts) 更新：
- 禁止访问 `data/users/*/agents/*/sessions/`（原 `data/sessions/`）
- 允许通过 read_agent_memory / write_agent_memory 工具访问当前 agent 的 MEMORY.md
- 禁止访问其他 agent 的 MEMORY.md
- 禁止访问归档文件夹 `data/users/*/archived-agents/`
- 禁止访问 ui-config.json

### 2.8 专业 agent 新建浮层 UI

#### 触发时机

- 侧边栏底部「+ 新建专业 agent」按钮
- 点击后居中弹出 modal

#### 浮层形式

- 居中模态（modal），约 560px 宽度
- 半透明黑色背景遮罩，点击遮罩不关闭（避免误丢内容）
- 单页分段（不分步）：所有表单在一个浮层里分段呈现
- 底部固定保存 / 取消按钮

#### 浮层内容（分段）

**身份配置区**：
- name 输入框（中英文随意，max 64）
- description 输入框（max 120 字符）
- slug 自动生成（用户不感知）

**性格配置区**：
- personality 多行文本框（systemPrompt body）
- placeholder 范例：「你是___助手，语调___，重点___」
- 可选填写（留空则使用通用 systemPrompt 作为 fallback）

**记忆配置区**：
- 是否启用跨 session 记忆（toggle，默认开）
- 初始记忆内容（可选手动预填，留空则创建空 MEMORY.md）
- 提示文字：「记忆会跨会话积累，agent 越用越懂你」

**LLM 配置区**：
- model 选择（从 config.providers 的所有可用 model 下拉选）
- temperature 滑块（0-2，默认 0.7）
- maxTokens 输入框（默认 4096）
- reasoningEffort 选择（low/medium/high）
- thinkingType 选择（enabled/disabled）
- thinkingBudgetTokens 输入框（仅 thinkingType=enabled 显示）

#### 创建后的副作用

1. 创建 `data/users/<userId>/agents/<slug>/` 目录
2. 生成 AGENT.md（含 frontmatter + personality body + LLM 配置）
3. 若启用记忆，生成空 MEMORY.md（或预填内容）
4. 自动新建一个 session（agentId=新 agent，继承 agent 的 LLM 配置）
5. 前端关闭浮层，跳转到新 session
6. 侧边栏新增该 agent 节点，下方挂载新 session

### 2.9 通用 agent 与专业 agent 设置浮层

#### 通用 agent 设置浮层

- 标题：「通用助手设置」
- 内容：LLM 配置区 + Skill 展示配置区（0.3.0 仅这两项，后续版本可扩展其他设置）
- 无 personality 配置（systemPrompt 固定）
- 无删除按钮（default 不可删除）

#### 专业 agent 设置浮层

- 标题：「编辑 agent」
- 内容：身份配置区 + 性格配置区 + 记忆配置区 + LLM 配置区
- 编辑时 name 可改（slug 不可改），其他字段可改
- 含删除按钮（带确认弹窗 + 归档流程）

### 2.10 独立 LLM 配置的分层

- **agent 级**：AGENT.md frontmatter 的 LLM 配置（影响新会话）
- **session 级**：现有 `/session` 命令的动态属性（保留，作为 session 级覆盖）
- session 创建时继承 agent 的 LLM 配置作为初始值，session 级可调整

## 3. Mode A skill 选择 UI

### 3.1 核心原则

- **不动 skill 文件本身**：不修改 skill frontmatter 的 display / displayName 字段
- **不动 AGENT.md**：不写入 visibleSkills，这是 UI 层面的显示控制
- **仅在 default agent 的 UI 设置中管理**：存储为 UI 层配置

### 3.2 skill chip 区位置

聊天框上方（仅 default agent 会话显示，专业 agent 会话不显示）：

```
┌──────────────────────────────────────────────┐
│ Skills:  [通用翻译] [代码生成] [总结文档]      │  ← 长方块平铺
├──────────────────────────────────────────────┤
│  请翻译以下内容，目标语言：__                  │  ← 输入框（智能填充模板）
│  ┃                                            │
│                                              │
└──────────────────────────────────────────────┘
```

### 3.3 skill 展示机制（配置驱动）

**配置存储**：
- 位置：`data/users/<userId>/agents/default/ui-config.json`
- 字段：
  - `visibleSkills`：array of `{ slug: string, displayName: string }`
  - 仅记录「展示在 chip 区」的 skill，未记录的 skill 不展示

**配置来源**：
- 全局已加载的所有 skill（`~/.aptbot/skills/` + `src/skills/`）作为「可选池」
- default agent 的 ⚙️ 设置浮层中「Skill 展示配置」区管理
- 每个 skill 有 checkbox（是否展示）+ displayName 输入框（自定义展示名称）
- 保存后写入 ui-config.json

**配置优先级**：
1. ui-config.json 的 visibleSkills（最高优先级）
2. 未配置时 chip 区不显示（沿用 0.2.2 默认行为）

### 3.4 chip 交互

- 仅 visibleSkills 列表中的 skill 展示为 chip
- chip 显示 displayName（未设置时用 name）
- chip 数量少时直接平铺，数量多时横向滚动（暂不优化排布）
- 点击 chip 后：
  - 智能填充模板到输入框（空则覆盖，有则追加）
  - 若模板含 `{{cursor}}` 占位符，光标自动定位到该位置
  - 选中的 chip 高亮显示（可再点取消）
- 没有任何 visibleSkills 时，chip 区不显示

### 3.5 skill 元数据扩展

[skill 文件](file:///Users/evan/projects/aptbot/src/core/skills/types.ts) frontmatter 仅新增 1 个字段：
- **template**：提示词模板字符串
  - 点击 skill 后填入输入框的模板
  - 可含 `{{cursor}}` 占位符标记光标停留位置
  - 未设置时模板为空，仅激活该 skill（用户直接输入）

不新增 display / displayName 字段（这两个是 UI 层配置，不动 skill 文件）。

### 3.6 skill 不持久化

- skill 选择状态不写入 SessionMetadata
- 一次性使用：用户选择 skill 后模板填入输入框
- 后续对话中 agent 自行判断是否还需要继续使用该 skill
- 用户可立即切换其他 skill
- 刷新页面后 skill 选择清空（无 activeSkill 字段）

### 3.7 不实现

- 不动 skill 文件本身
- 不动 AGENT.md
- 不实现 chip 排序 / 拖拽
- 不实现 chip 添加 / 移除 UI（在 ⚙️ 设置浮层管理）
- 不实现 skill 搜索框
- 不实现 skill 启用/禁用 toggle
- 不实现分类 chips（数量少，平铺即可）

## 4. Mode B 共享记忆机制

### 4.1 上下文注入策略（KV 缓存 + 前部稳定）

**自动注入**：MEMORY.md 内容自动注入到 systemPrompt，每 turn 都包含。

**KV 缓存设计**（避免每 turn 重复 token 计费）：

systemPrompt 结构（前部稳定 + 后部追加）：
```
[固定前部 - 稳定区]
你是 ___ 助手...
安全约束...
工具说明...

[MEMORY.md 内容 - 半稳定区]
User Profile: ...
Facts: ...
Preferences: ...
History: ...

[当前 turn 上下文 - 变化区]
用户消息...
工具调用结果...
```

**稳定机制**：
- 固定前部 + MEMORY.md 内容共同构成「前部稳定区」
- KV 缓存命中时，前部稳定区不重新计费
- 新的记忆追加在 MEMORY.md 末尾（History section 内追加），不破坏前部缓存
- 仅当 MEMORY.md 前部内容被修改时才触发缓存失效（极少发生）

**实施约束**：
- agent 写入 MEMORY.md 时优先 append（追加到 section 末尾），避免修改前部
- 工具说明、安全约束等固定文本不放在 MEMORY.md 之后（保持前部稳定）

### 4.2 read_agent_memory 工具

agent 主动读取 MEMORY.md（用于刷新或分段读取）：
- 读取范围：仅当前 agent 的 MEMORY.md
- 路径约束：工具内部硬编码 `data/users/${currentUserId}/agents/${currentAgentId}/MEMORY.md`，不接受路径参数
- 大小限制：>8KB 返回 `memory_too_large`，提示按 section 分段读取
- 不存在时返回空内容（非错误）
- 跨 agent 访问禁止（路径硬编码当前 agentId）

### 4.3 write_agent_memory 工具（自动写入）

**核心机制**：agent 自主判断是否需要写入，无用户确认环节。

流程：
1. agent 调用 write_agent_memory 工具，提交 section + content + mode（append/replace）
2. 工具直接写入（write-to-tmp + rename 原子操作）
3. 工具返回写入结果给 agent
4. 同步记录审计日志

**写入约束**：
- 单次写入 content 长度限制：max 2KB（防止 OOM）
- 仅专业 agent + 启用记忆时可用
- 路径硬编码当前 agentId，禁止跨 agent 写入
- append 模式：追加到指定 section 末尾
- replace 模式：替换整个 section 内容（较少使用）

### 4.4 审计日志

**存储**：
- 文件：`data/users/<userId>/agents/<slug>/memory.log.jsonl`
- 格式：JSONL append-only，每行一条写入记录
- 复用现有 jsonl-mutex.ts per-file mutex

**字段**：
- timestamp：ISO 8601
- sessionId：触发写入的 session
- section：写入的 section（User Profile / Facts / Preferences / History）
- mode：append / replace
- contentPreview：写入内容前 200 字符（预览）
- contentLength：写入内容总长度
- beforeSize：写入前 MEMORY.md 文件大小
- afterSize：写入后文件大小

**访问**：
- CLI：`/agent memory-log [limit]` 列出最近 N 条（默认 20）
- WebUI：agent 设置浮层「记忆写入日志」区，展示最近 20 条
- 不实现修改 / 删除日志（append-only）

**审计范围**：
- 仅 write_agent_memory 工具触发写入时记录
- 自动压缩触发写入也记录（mode: replace, contentPreview: "auto compress"）
- 不记录 read_agent_memory（读取不审计）

### 4.5 写入时 UI 轻量提示

- agent 写入记忆时，UI 展示轻量提示（如「agent 已更新记忆：Preferences」）
- 提示不打断对话，仅作告知
- 0.3.0 实施基础提示（toast / inline message），具体形式实施时确定

### 4.6 MEMORY.md 压缩机制（>8KB 触发）

当 MEMORY.md 超过 8KB 软上限时：
- read_agent_memory 返回 `memory_too_large`，提示 agent 需要压缩
- agent 调用压缩工具（或自主压缩）：
  - History section：旧条目合并摘要（保留最近 N 条详细，更早的合并）
  - 其他 section：合并冗余条目、删除过时内容
- 压缩后写入替换整个 MEMORY.md（mode: replace）
- 0.3.0 实施基础压缩（agent 自主压缩 + write_agent_memory replace 模式）
- 0.3.1 实施自动压缩触发（每次 read 检测大小 + 自动触发压缩提议）

## 5. 迁移策略、HTTP API、删除流程

### 5.1 迁移策略

#### 现有 sessions 自动迁移

0.3.0 升级时，扫描 `data/sessions/*.jsonl` + `.meta.json`，按 userId 分组迁移：

- 有 userId 的 session → 迁移到 `data/users/<userId>/agents/default/sessions/<id>.jsonl`
- 无 userId 的 session → 为匿名生成 UUID 作为伪 userId，创建 default agent 归属
- 为每个 userId 创建 default agent 的 AGENT.md（若不存在）
- 更新 .meta.json 添加 `agentId: default`

#### default agent 配置

- 每个用户首次访问时自动创建私有 `default` agent
- AGENT.md body 使用当前 systemPrompt（向后兼容）
- type=default
- 不可删除（可编辑设置）

#### 迁移的幂等性

- 迁移中断后重新运行可继续
- 已迁移的 session 不重复迁移（检查目标路径是否存在）
- 已创建的 default agent 不重复创建（检查 AGENT.md 是否存在）

### 5.2 HTTP API 扩展

#### Agent 管理 API

| 端点 | 方法 | 行为 |
|---|---|---|
| `/api/agents` | GET | 列出当前用户的所有 agents |
| `/api/agents/:slug` | GET | 获取 agent 详情（含 AGENT.md + LLM 配置） |
| `/api/agents` | POST | 创建新 agent（专业 agent） |
| `/api/agents/:slug` | PUT | 更新 agent 配置（personality / LLM / 记忆开关） |
| `/api/agents/:slug` | DELETE | 删除 agent（仅专业 agent，default 不可删） |
| `/api/agents/:slug/sessions` | GET | 列出该 agent 的 sessions |
| `/api/agents/:slug/memory` | GET | 获取 MEMORY.md 内容 |
| `/api/agents/:slug/memory-log` | GET | 获取写入审计日志 |

#### UI 配置 API（仅 default agent）

| 端点 | 方法 | 行为 |
|---|---|---|
| `/api/agents/default/ui-config` | GET | 获取 UI 配置（含 visibleSkills） |
| `/api/agents/default/ui-config` | PUT | 更新 UI 配置 |

#### Skill 管理 API

| 端点 | 方法 | 行为 |
|---|---|---|
| `/api/skills` | GET | 列出所有已加载 skill（含 template 字段） |

### 5.3 关键交互约束

1. **session 切换跟随点击**：点击左侧某个 agent 下的会话，自动进入该 session，不存在「保持」问题
2. **跨用户隔离**：所有 agent 操作校验 `agent.userId === currentUserId`
3. **路径遍历防护**：agentSlug 严格正则 `/^[a-z0-9-]{3,64}$/`

### 5.4 删除专业 agent 流程

#### 删除流程

1. 用户点击专业 agent ⚙️ 设置 → 删除按钮
2. 弹出确认弹窗：「确定删除 agent 'XXX'？所有会话将归档。」
3. 用户确认后：
   - agent 配置 + 所有 sessions 移动到归档文件夹
   - 归档路径：`data/users/<userId>/archived-agents/<slug>-<timestamp>/`
   - 包含：AGENT.md + MEMORY.md + sessions/ + memory.log.jsonl
   - 从 active agent 列表移除
   - 前端关闭设置浮层 + 跳转到 default agent
4. 归档文件夹保留在 `archived-agents/` 下，不自动清理

#### 归档文件夹的彻底清除

- 归档文件夹可在文件系统中查看 / 恢复 / 删除
- 用户在归档文件夹中删除（手动或通过文件管理器）才彻底清除
- 0.3.0 不实现归档管理 UI（YAGNI）

#### 不实现

- 不实现「恢复归档 agent」UI（YAGNI，用户可手动移回）
- 不实现归档列表查看 API（YAGNI）
- 不实现自动清理过期归档（YAGNI）

## 7. 错误处理与边界

### 7.1 错误处理场景

| 场景 | 处理 |
|---|---|
| AGENT.md 不存在/损坏 | fallback 到 default agent systemPrompt + warn |
| MEMORY.md 不存在 | read_agent_memory 返回空内容（非错误） |
| MEMORY.md > 8KB | 返回 `memory_too_large`，提示 agent 压缩 |
| write_agent_memory 失败（IO 错误） | 工具返回错误 + 不写入 + 审计日志记录失败 |
| write_agent_memory 并发写入 | per-agentId mutex 串行化 |
| agentId 不存在 | `/agent <slug>` 返回错误 + 列出可用 agents |
| 跨用户访问 agent | HTTP 403 + WebSocket 忽略 |
| 迁移中断 | 幂等设计，重新运行可继续 |
| 删除专业 agent 时归档失败 | 拒绝删除 + 错误提示 |
| ui-config.json 损坏 | fallback 到空 visibleSkills（chip 区不显示）+ warn |
| skill template 含 `{{cursor}}` 但解析失败 | 当作普通文本处理（光标默认在末尾） |

### 7.2 边界约束

#### 路径遍历防护

- agentSlug 严格正则 `/^[a-z0-9-]{3,64}$/`
- userId 严格校验（UUID 格式）
- 所有路径拼接前校验各段格式

#### 跨用户隔离

- 所有 agent 操作校验 `agent.userId === currentUserId`
- HTTP API 返回 403
- WebSocket 忽略非法请求

#### 文件操作原子性

- AGENT.md / MEMORY.md 写入：write-to-tmp + rename 原子操作
- 审计日志：JSONL append-only（复用现有 jsonl-mutex）
- 归档操作：先复制到归档路径 + 验证完整性 + 再删除原路径

#### 并发写入

- per-agentId mutex：保护 AGENT.md / MEMORY.md 并发写入
- per-file mutex：保护 memory.log.jsonl 并发 append（复用现有 jsonl-mutex）

### 7.3 容量与性能边界

| 场景 | 限制 |
|---|---|
| MEMORY.md 软上限 | 8KB（超出触发压缩） |
| 单次 write_agent_memory content | max 2KB（防止 OOM） |
| 单个用户 agent 数量 | 软上限 50（超出 warn，不阻塞） |
| 单个 agent sessions 数量 | 沿用 0.2.x 限制 |
| memory.log.jsonl 大小 | 不限制（YAGNI，写入频率低） |

### 7.4 安全约束

#### systemPrompt 约束更新

[systemPrompt](file:///Users/evan/projects/aptbot/src/server.ts) 更新：
- 禁止访问 `data/users/*/agents/*/sessions/`（原 `data/sessions/`）
- 允许通过 read_agent_memory / write_agent_memory 工具访问当前 agent 的 MEMORY.md
- 禁止访问其他 agent 的 MEMORY.md
- 禁止访问归档文件夹 `data/users/*/archived-agents/`
- 禁止访问 ui-config.json

#### 鉴权

- HTTP API：复用现有 authToken 机制
- WebSocket：复用现有 WS token 三级优先级
- CLI：本地运行，复用 AgentSession auth 上下文
